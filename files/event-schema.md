# Canonical Event Schema (THE most important contract)

Every module that touches an event — CV, Tracking, GPS/Event builder, Backend, DB,
Intelligence, Frontend — reads/writes **this exact shape**. Field names and types never
change without full-team sign-off.

## Field table

| Field | Type | Required | Notes |
|---|---|---|---|
| `event_id` | string | generated by backend on insert | Format: `EVT_<ULID>` e.g. `EVT_01J8X8G3K2Q7...`. Client-side (CV/tracking) events use a temporary `client_event_id` instead (see below). |
| `client_event_id` | string | yes (from producer) | UUID4 generated by the event-builder module before it reaches the backend. Used for idempotency (retry-safe ingestion). |
| `event_type` | enum string | yes | One of the canonical detection classes — see `detection-classes.md`. e.g. `"pothole"`. |
| `source_bus` | string | yes | Format: `BUS_<2-4 digit id>` e.g. `BUS_17`. |
| `route_id` | string | optional | Format: `ROUTE_<id>`. Optional in prototype since routes may not be modeled yet. |
| `timestamp` | string (ISO 8601, UTC) | yes | Format: `YYYY-MM-DDTHH:MM:SSZ`. Always UTC, always `Z` suffix. This is the detection time, not ingestion time. |
| `latitude` | float | yes | WGS84, decimal degrees, range `-90..90`. |
| `longitude` | float | yes | WGS84, decimal degrees, range `-180..180`. |
| `gps_source` | enum string | yes | `"simulated"` \| `"real"`. **Must never be omitted** — see Rule 9. |
| `gps_accuracy_m` | float | optional | Estimated accuracy in metres. `null`/omitted if unknown (typical for simulated GPS). |
| `confidence` | float | yes | YOLO detection confidence, range `0.0..1.0`. |
| `severity` | enum string | yes | `"low"` \| `"medium"` \| `"high"` \| `"critical"`. Initial value set by CV/event-builder using simple heuristics (see below); may be recalculated by Intelligence engine. |
| `tracking_id` | string | optional | ByteTrack object ID, scoped to one video/bus session. Lets you trace an event back to a tracked object. |
| `road_segment_id` | string | optional | Filled in by geospatial module once matched to `ROAD_SEGMENT` table. Null until matched. |
| `frame_ref` | string | optional | Path/URI or frame index + video id, e.g. `"BUS_17/session_2026-08-27T14/frame_00452.jpg"`. Used for human verification, not required for pipeline logic. |
| `status` | enum string | yes (defaults `OPEN` on creation) | See `state-machine.md` for full enum + transitions. |
| `incident_id` | string | optional | Set once deduplication links this event to an `Incident`. Null on first-ever sighting until dedup runs (may be same request cycle). |
| `metadata` | object | optional | Free-form key/value bag for anything module-specific (e.g. `{"weather": "rain", "vehicle_subtype": "truck"}`). Never put required fields inside `metadata` — if it's required, it gets promoted to a top-level field. |
| `created_at` | string (ISO 8601 UTC) | server-set | Row insert time in DB. |
| `updated_at` | string (ISO 8601 UTC) | server-set | Last modification time. |

## Enum values

- `event_type`: see `detection-classes.md` — canonical list, e.g. `pothole`, `waterlogging`,
  `vehicle_car`, `vehicle_bus`, `vehicle_truck`, `vehicle_motorcycle`, `traffic_sign`,
  `traffic_light`, `road_divider`, `zebra_crossing`, `pedestrian`, `streetlight`.
- `severity`: `low`, `medium`, `high`, `critical`
- `gps_source`: `simulated`, `real`
- `status`: `OPEN`, `ACKNOWLEDGED`, `IN_PROGRESS`, `RESOLVED`, `PENDING_VERIFICATION`,
  `VERIFIED`, `DISPUTED`, `RE_ESCALATED` — full detail in `state-machine.md`.

## ID formats

- `event_id`: `EVT_<ULID>` — sortable, unique, generated server-side on insert.
- `client_event_id`: UUID4, generated client-side (by the event-builder module) so retries
  from a flaky network don't create duplicate rows (backend upserts on this key).
- `incident_id`: `INC_<ULID>`.
- `source_bus`: `BUS_<id>`.
- `road_segment_id`: `SEG_<id>`.
- `route_id`: `ROUTE_<id>`.

## Initial severity heuristic (placeholder, CV/event-builder sets this; Intelligence may override)

- `critical`: waterlogging with confidence > 0.85, or pothole with confidence > 0.9
- `high`: pothole confidence 0.7–0.9
- `medium`: pothole confidence 0.5–0.7, or traffic_light/sign malfunction flags
- `low`: everything else (default)

This is intentionally crude — Member 5's Priority Engine (see `module-contracts.md`) is the
real scoring logic. `severity` on the raw event is just a fast, explainable starting point so
the pipeline is demoable even before Intelligence is wired in.

## Validation rules

- `latitude`/`longitude` must be valid WGS84 floats within range; reject otherwise (HTTP 422).
- `confidence` must be in `[0,1]`.
- `event_type` must be in the canonical enum — reject unknown types rather than silently
  accepting free text.
- `timestamp` must parse as ISO 8601 UTC.
- `gps_source` is required — never assume; an omitted value is a validation error, not a
  default, because we must never let simulated GPS silently pass as real GPS (Rule 9).

## Ingestion payload (what CV/Tracking/GPS module actually POSTs)

The producer does not send `event_id`, `incident_id`, `created_at`, `updated_at`, or `status`
(server sets these). It sends:

```json
{
  "client_event_id": "3fae2b0e-9b2c-4b0b-9c39-5b6e0f9c9a11",
  "event_type": "pothole",
  "source_bus": "BUS_17",
  "route_id": "ROUTE_42",
  "timestamp": "2026-08-27T14:20:00Z",
  "latitude": 28.6139,
  "longitude": 77.2090,
  "gps_source": "simulated",
  "confidence": 0.91,
  "severity": "high",
  "tracking_id": "TRK_58",
  "frame_ref": "BUS_17/session_2026-08-27T14/frame_00452.jpg",
  "metadata": {"weather": "clear"}
}
```

The formal JSON Schema lives at `data/contracts/event.schema.json` (Backend + Geospatial
owners maintain it; treat it as generated from this doc, not the other way around).
